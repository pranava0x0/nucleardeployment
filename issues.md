## Resolved

- 2026-08-05 — DATA-003: The homepage called Vogtle Units 3 and 4 "the only new U.S. nuclear this century." That is false. Watts Bar Unit 2 added 1,150 MW in 2016, the first U.S. reactor to come online since 1996, though its construction began in 1973 and was suspended between 1985 and 2007. Root cause: **spec bug carried into code**. `docs/plan-gigawatt-race.md` asserted it as the editorial anchor and the claim was copied without checking, which is the failure the project's own "a spec's data assumptions are guesses until you query the data" rule exists to prevent. The homepage now says "most recent" and claims only what the sourced Vogtle record supports; the spec carries a dated correction. Found by the pull-request bot, verified independently against EIA before fixing.
- 2026-08-05 — DATA-004: The Westinghouse race row was rated 300 MWe on the AP300 and rendered "a gigawatt is 4 × 300 MWe units", while its own roster basis read "AP300 has no named U.S. site." The row asserted a grid-scale U.S. position that its own evidence denied, and mixed two reactor designs in one entry. Root cause: **data bug**. The company's only documented U.S. reactor program is the eVinci experiment at DOE's DOME test bed, so the entrant is now the 5 MWe eVinci in the microreactor lane, with the AP300 recorded in the rating note as having no U.S. site. Guarded by a test asserting every roster basis states what a company has rather than what it lacks, verified to fail against the original wording.
- 2026-08-05 — UI-005: The `/companies` directory rendered an empty `<b></b>` for the deployment stage of a roster entrant with no tracked project, while `/companies/[slug]` handled the same case explicitly. Root cause: **code bug**, a fix applied to one of two render paths. NuScale and GE Vernova Hitachi were the first companies with an empty `projectSlugs`. Both paths now state "No tracked project". Guarded twice: a sweep asserting no text-carrying element renders blank on any of the 33 pages, and a count assertion tying the directory's explicit states to the number of projectless companies.

- 2026-08-05 — A11Y-002: Every interactive control on the race board and the company dossiers was 24 px tall at 375 px, and the stylesheet contained no `@media (pointer: coarse)` rule at all, so the project's 44 px touch floor had never been applied anywhere. Root cause: **code bug**, an omission in the new components rather than a broken rule. Measured in a real browser at 375 px: 18 board links plus the dossier back link and source link were under the floor. Added a coarse-pointer block covering the board links, ledger source links, roster-basis link, back link, and company-summary links; re-measured at 0 under target. Guarded by a stylesheet test that asserts the block exists, sets 44 px, and names each selector, proven to fail when the media query is switched to `pointer: fine`.
- 2026-08-05 — UI-004: The race legend's swatch for the "under review" band rendered as a plain grey hairline instead of the 2 px blue outline the bars use, so the legend taught an encoding the board did not use. Root cause: **code bug**, a cascade-order mistake. `.legend-swatch` was declared after the `.band-*` rules and its border out-ranked theirs at equal specificity. Moved the swatch declaration above the band rules. Guarded by a test asserting the declaration order, which also checks both rules exist because `indexOf` returns -1 for a deleted rule and would otherwise pass.
- 2026-08-05 — A11Y-003: A company with a real but unquantified framework agreement (Aalo, BWXT) had an `aria-label` reading "0 MWe announced, non-binding" while its visible caption read "capacity not disclosed". A screen-reader user was told the opposite of what the page showed: no agreement, rather than an agreement of undisclosed size. Root cause: **code bug** in the label builder, which formatted every zero identically. The label now distinguishes an undisclosed capacity from a genuine zero. Guarded by a test asserting the literal text in both directions, after the first version of that test proved vacuous: it compared the rendered output against the same function that produced it, so it could never fail.

- 2026-08-05 — CI-001: `npm test` could not run on the Node version this project pinned and declared. `tests/rendered-html.test.mjs` imports `app/data.ts` directly, which needs Node's unflagged TypeScript type stripping, released in 22.18.0. `package.json` declared `engines.node >=22.13.0` and both workflows pinned 22.13.0, so the three tests asserting source-link, DOE-program, and reactor-taxonomy invariants threw `ERR_UNKNOWN_FILE_EXTENSION` and never ran in CI. They passed locally only because the development machine runs 22.22.1. Root cause: **config bug**, not a test bug — the declared Node floor sat below the suite's real requirement. Raised `engines` to `>=22.18.0` and pinned both workflows to exactly 22.18.0, so CI runs the oldest supported Node. Reproduced before and after with `node --no-experimental-strip-types --test`, which fails tests 5–7 and passes all 12 once stripping is on. Found by the pull-request gate on its first run, which is what the gate was added for.
